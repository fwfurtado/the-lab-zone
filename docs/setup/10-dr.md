# Setup Fase 10 — DR

Objetivo: backup/restore validado de ponta a ponta — sai de "tenho backup" para "sei que
restauro". Lição transversal: **status verde é promessa; a prova é ler o destino.**

Três pilares: perna off-site Garage→B2; Velero (objetos K8s + FSB); CNPG backup real (achado da
fase: o Postgres estava sem backup nenhum desde 15/06 — ver runbook backup-dr). Destino de DR é
**sempre B2** (off-site); Garage é tier on-site.

## Pré-requisitos manuais (one-way `op → repo`)
- **Buckets B2 (Terraform):** adicionar `the-lab-zone-dr` (retention 60d) e `the-lab-zone-velero`
  (60d) em `infra/prod/buckets/b2/variables.tf`; `just tf-apply`.
- **App keys B2 (console → 1Password vault `the-lab-zone`):** `b2-dr-sync` e `b2-velero`
  (accessKeyId, secretKey; list/read/write/delete no respectivo bucket). `keyName`=accessKeyId,
  `applicationKey`=secretKey (só aparece uma vez).
- **Garage read key (espelho):** `just garage generate-key --keyname=dr-sync`; dar `--read` nos
  buckets `cnpg-wal clickhouse-backup qdrant-snapshots langfuse`; confirmar SÓ read.

## 10.A — Perna off-site Garage→B2
`apps/data/offsite-sync/`: ExternalSecret `dr-offsite-credentials` (garage-dr-sync read +
b2-dr-sync write); WorkflowTemplate + CronWorkflow `offsite-sync` (a cada 2h): `rclone copy` pros
append-only e `rclone sync` pro langfuse. `podMetadata.labels: app.kubernetes.io/name:
offsite-sync` (identidade Cilium); adicionar `offsite-sync` aos `fromEndpoints` do `:3900` na CNP
do Garage. RPO off-site do Postgres = 2h.

## 10.B — Velero
`apps/core/velero/`, chart `vmware-tanzu/velero` 8.7.2 (Velero 1.15.2). Pontos críticos:
- `upgradeCRDs: false` (o job puxa `bitnami/kubectl`, que sumiu do Docker Hub; o ArgoCD já aplica
  os CRDs do `crds/`).
- `initContainers: velero-plugin-for-aws:v1.11.1` (casa Velero 1.15.2; v1.12.x quebra).
- `uploaderType: kopia`, `defaultVolumesToFsBackup: false`, `volumeSnapshotLocation: []`.
- BSL `b2`: region `us-east-005`, `s3ForcePathStyle: "true"`, `s3Url: https://s3.us-east-005.
  backblazeb2.com`, bucket `the-lab-zone-velero`.
- `metrics.serviceMonitor.enabled: false` (usamos VMPodScrape — **só matchLabels, SEM
  matchExpressions**, senão o target não é gerado).
- Namespace com PSA `privileged` (node-agent); ExternalSecret `velero-b2-creds`.
- Schedules: `cluster-meta` (objetos K8s, sem FSB) e `stateful-orphans` (FSB só Memgraph).

## 10.C — CNPG: backup via Barman Cloud Plugin
Migrar do in-tree (a imagem `-standard` não tem barman) pro plugin.
- **Plugin:** `apps/core/barman-cloud-plugin/` apontando pro release v0.5.0 (commitado), instala
  no ns `cnpg-system`. Pré-req cert-manager.
- **ObjectStore:** as 4 envs do Garage são obrigatórias (`BARMAN_S3_USE_PATH_STYLE=true`,
  `AWS_DEFAULT_REGION=garage`, `AWS_REQUEST_CHECKSUM_CALCULATION=when_required`,
  `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required`); `destinationPath: s3://cnpg-wal/`,
  `endpointURL: http://garage.data.svc.cluster.local:3900`.
- **Cluster (manifesto cru):** substitui o chart (que não expressa `.spec.plugins`); sem
  `.spec.backup`, com `plugins: [barman-cloud... isWALArchiver: true]`. Update in-place (SSA).
- **ScheduledBackup** `method: plugin`.
- **CNP do Garage:** adicionar `cnpg.io/cluster: cnpg-cluster` ao `:3900`.
- **Restart do operator** pra redescobrir o plugin (senão `wal archive plugin is not available`).
